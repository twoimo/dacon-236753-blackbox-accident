# Stage 1 — 재녹화 여부 판별 (ORIGINAL vs RERECORDED)

- **과업**: 블랙박스 영상이 원본인지, 화면/기기로 다시 촬영한(recapture) 영상인지 이진 분류.
- **지표**: Macro-F1 (두 클래스 F1 동일 가중). **가중치 0.2.**
- **근거 정본**: `research/references/README.md`. 인용은 Key로 표기.

---

## 1. 문제의 본질 — 재촬영은 "제2의 촬영 체인"

재촬영 영상은 원본 위에 **디스플레이 → 광학계 → 센서** 의 두 번째 획득 과정이 덧씌워진다.
문헌이 반복 확인한 물리적 흔적은 다음 세 가지다.

1. **모아레(moiré)**: 디스플레이 픽셀 격자와 카메라 센서 격자의 간섭. 광대역 주파수에 걸쳐
   나타난다 (`sun2018moire`, IEEE TIP 2018). 단일 3×3 고역통과로는 못 잡는다.
2. **엣지 번짐 / MTF 변화**: 디스플레이 MTF + 렌즈로 엣지 스프레드가 바뀐다
   (`thongkamwitoon2015recapture`, IEEE TIFS 2015). 모아레가 안 보이는 "깨끗한" 재촬영도
   엣지 지문은 남는다.
3. **잔상·시간 아티팩트(ghosting)**: 리프레시율 vs 셔터의 박자, 롤링셔터 → 시간축으로
   움직이는 아티팩트 (`dai2022videodemoire`, CVPR 2022). 즉 재촬영은 **프레임 1장이 아니라
   클립 단위(시공간)** 로 봐야 한다.

## 2. 최우선 위험 — 코덱 누설 (Codec Leakage)

**이 대회에서 가장 크고 조용한 함정.** `docs/05-data-integrity-report.md` 와 대회 데이터 유래상:

- 공개 예제 ORIGINAL = 전부 mpeg4, RERECORDED = 전부 h264.
- 그냥 학습하면 모델은 "재촬영"이 아니라 "**어떤 코덱인가**"를 외운다.

이중압축/코덱 포렌식 문헌이 이 위험을 정면으로 입증한다.

- `wangfarid2006double` (ACM MM&Sec 2006, ~267 cites): 이중 MPEG 압축은 주기적 잔차 패턴을 남겨
  **매우 학습되기 쉽다.**
- `jiang2019hevc` (IEEE TIFS 2019): **동일한 코딩 파라미터로 재압축해도** intra 품질 저하 흔적이
  남는다. 즉 CRF만 맞춘다고 숨길 수 없다.

**대응 원칙:**
- 재촬영 합성 후 **원본과 재촬영을 똑같은 랜덤 ffmpeg 분포**(코덱·CRF·GOP·fps)로 통과시켜,
  라벨이 "재인코딩 여부"와 상관되지 않게 만든다.
- 컨테이너 메타데이터·비트레이트·profile·파일크기를 **분류기 입력으로 절대 넣지 않는다.**

## 3. 두 번째 위험 — 합성 모아레의 도메인 갭

`luo2021sadg` (문제정의용 인용): 한 세팅의 합성 모아레로 학습한 검출기는 **디바이스/스케일
시프트에서 붕괴**한다. Photoshop식 사인파 오버레이만 쓰면 그건 "재촬영 검출기"가 아니라
"특정 모아레 주기 분류기"가 된다.

또한 모아레는 **필요조건도 충분조건도 아니다.** OLED, 약한 디포커스, 디모아레잉(demoiréing)은
줄무늬를 없앤다. 그래도 엣지/MTF(`thongkamwitoon2015recapture`)와 잔상(`dai2022videodemoire`)
단서는 남는다. → "줄무늬만 찾는" 헤드는 깨끗한 재촬영을 놓친다.

## 4. 권장 접근 (근거 기반)

### 백본 — 잔차 + 시간 2-스트림
- **Stream A (RGB/gray)**: 저주파 색/감마, 잔상.
- **Stream B (제약 잔차)**: conv1을 고정 Laplacian/고역통과/SRM류로 초기화
  (`yang2017laplacian`). ImageNet 백본이 도로·차·날씨 같은 **콘텐츠**를 외우는 것을 막는다.
- **시간 창 8~16 프레임** (경량 3D 또는 X3D-S). 재촬영을 시공간으로 처리.
- (선택) 잔차의 FFT/DCT 진폭 헤드. 단, 작게 유지해 단일 합성 주파수를 외우지 못하게.

### 재촬영 합성 파이프라인 (물리 우선)
- **Tier 1 (물리)**: dashcam 클립을 여러 패널(IPS/VA/OLED, 60/120Hz)에 전체화면 재생 → 여러
  카메라/폰으로 거리·각도·노출·초점·손떨림 바꿔 재촬영 → 베젤 없는 크롭 → **두 클래스 동일 재인코딩.**
- **Tier 2 (광학 시뮬)**: 서브픽셀 격자 + 감마 + 미세 호모그래피 + 렌즈 MTF(엣지 번짐) +
  Poisson/read 노이즈 + 리프레시-셔터 박자. **클립마다 격자 주파수·위상을 랜덤화.**
- **Tier 3 (금지에 가까움)**: RGB에 사인파 모아레만 얹는 방식. 단독 학습 신호로 쓰지 않는다.

### 학습/검증 프로토콜
- **소스 영상 ID 기준 split** (프레임 랜덤 split 금지 — 누설).
- **최소 1개 화면 + 1개 카메라를 홀드아웃** (leave-one-device-out). 그 홀드아웃 Macro-F1이
  진짜 지표다. In-domain 정확도는 과대평가된다 (`patel2015moire` 가 cross-db에서 입증).
- 공개 Stage 1 예제는 **캘리브레이션용**으로만 섞는다.

## 5. 데이터 자산 연결
- CCD 75,000 프레임(`data/external/CrashBest/`) = 원본 dashcam 프레임 공급원.
  여기서 재촬영을 **합성**하고 두 클래스를 같은 코덱으로 재인코딩한다.
- 해상도 3종(1280×720 / 960×720 / 640×360) 혼재 → 필러박스(검은 띠)가 거짓 단서가 될 수 있으니
  크롭 정책을 두 클래스에 동일 적용한다 (`docs/05` 4번 함정).

## 6. 검증 가능한 실험 후크
- `env/configs/stage1.yaml` 의 `recapture_synthesis` / `reencode` 블록으로 합성·재인코딩을 제어.
- 하니스 지표: `METRIC macro_f1=<value>` + 보조 `METRIC lodo_macro_f1=<value>` (leave-one-device-out).
